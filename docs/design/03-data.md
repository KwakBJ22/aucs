# 03 데이터 설계 (요약)

모든 자료는 **어디서 왔는지, 언제 확인했는지, 밖에 보여도 되는지**를 함께 저장합니다. 사건과 물건을 섞지 않고, 같은 물건의 시간에 따른 변화를 보존합니다. 표 이름의 한글 뜻은 `docs/glossary.md`.

## 스키마
| 스키마 | 내용 |
|---|---|
| raw | 받은 그대로(JSON·파일 주소). 추가만, 절대 고치지 않음 |
| ref | 기준표. 규칙표는 적용 시작일·끝날·근거를 가짐 |
| core | 정리된 자료. 값마다 원문 위치 연결 |
| analysis | 계산 결과. engine_version + input_hash로 재현 가능. 다시 만들 수 있음 |
| app | 사용자 자료. 행 단위 접근 제한(RLS), 본인 자료만 |
| ops | 수집·작업·관리자 변경 기록 |

## 꼬리표 (모든 원천 행·추출값)
- `source_id`, `fetched_at`, `source_date`
- `display_policy`: public / owner_only / internal / blocked — API는 public이 아닌 것을 화면에 내보내지 않음
- `checksum`
- 시각은 네 가지를 따로: 받은 시각, 원문 작성일, 마지막 변경 확인 시각, 계산 시각

## 식별자
| 대상 | 키 | 예 |
|---|---|---|
| 사건 | case_id = 법원코드 + 사건번호 | B000250-2025타경55580 |
| 물건 | item_id = 사건 + 물건번호 | B000250-2025타경55580-1 |
| 물건 구성 | item_part_id = 물건 + 목록번호 | …-1-L1 |
| 회차 | round_id = 물건 + 매각기일 | …-1-20261020 |
| 문서 | doc_id = 사건 + 종류 + 받은 시각 (내용이 다르면 새 버전) | |
| 부동산 | pnu(19자리) + 동·호 | |
| 단지 | complex_id = 법정동코드 + 본번 + 부번 | |

## 문서에서 뽑은 값 (core.extracted_fields)
doc_id·page·bbox(원문 위치) / field·raw_text·value / method(text·ocr·manual) / confidence(0~1) / check_status(auto_ok·needs_review·confirmed·rejected) / corrected_by·corrected_at·previous_value.
핵심 항목(권리 종류, 접수일, 금액, 전입일, 확정일자, 배당요구일)이 needs_review이면 그 물건 판정은 **보류**.

## 자료 상태 (analysis.item_data_status)
물건·자료 종류별 한 줄. 모든 화면이 이 표만 봄. missing 미확보 / fetching 받는 중 / fetched·extracted 확보 / needs_review 확인 필요 / verified (표시 없음) / stale 오래됨·날짜 / error 오류 / restricted 표시 안 함.

## 원천
| 원천 | 주기 | 외부 표시 |
|---|---|---|
| 법원 물건상세 | 매일(서울·경기, 천천히) | 가능(출처 표시) |
| 법원 문서(명세서·현황조사서·문건송달·기일) | 관심·임박 우선, 매일 | 가능(출처 표시) |
| 법원 감정평가서 | 위와 같음 | **숨김**(협회 확인 전) |
| 법원 매각결과 | 매일(최근 1주만 보임) | 가능 |
| 국토부 실거래 | 매일(최근 3개월 다시) | 가능 |
| 건축물대장 / 토지이용계획(vworld) | 물건이 생길 때 | 가능 |
| 공시가격 | 연 1회 | 가능 |
| 정비사업(서울) | 3개월 | 가능 |
| K-apt | 월 1회 | 가능 |
| 등기부 | 사용자 업로드 | 올린 본인만 |
| 사용자 임장 기록 | 앱 입력 | 본인만 |
| 사용자 입찰 결과(app.bid_results) | 앱 입력 | 통계만 |
| 온비드 공매 | 2단계 | 가능, 경매와 섞지 않음 |
| 지지옥션 | — | **금지**, 운영 서버에 올리지 않음 |

## 수집·보관 규칙
- 법원 사이트는 천천히(요청 사이 1초, 사건 사이 3초), 이상하면 즉시 멈춤. 로그인 없이, 차단 우회 금지.
- 관심 물건 서류: 담은 즉시 1번 → 7일마다 → 기일 7일 안이면 매일 → 기일 뒤 결과 1번.
- 서류 보관: 서울·경기 아파트, 기일 14일 안 1번 → 7일 안 1번 → 기일 뒤 1번, 하루 최대 150건.
- 다시 받을 때 비어 온 종류는 예전 것을 둠.
- 이름 가림: 원본은 보관, 화면에는 가린 보기만.
- raw 영구 보관(개인정보 문서는 종결 후 기간을 정해 이름 지운 본만). 사용자 등기부·임장 기록은 탈퇴 시 삭제. 정보 삭제 요청 창구·기록.
- 로컬 DuckDB는 설계 참고용. 다시 받을 수 없는 자료(과거 매각결과·실거래)만 한 번 옮김. 지지옥션 자료는 옮기지 않음.
